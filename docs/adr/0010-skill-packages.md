# Skill packages and discovery

Skills reuse the existing executor, workspace command tools, approvals, task records, and artifact storage; no separate script runtime is introduced. The format is the Agent Skills `SKILL.md` package, but discovery, precedence, and permission behavior are Meldra's own policy rather than compatibility with another agent's extensions, installers, or slash commands. `$name` names a skill to the model; it is not a frontend-enforced command.

Discovery scans direct `<name>/SKILL.md` children in this order: workspace `.meldra/skills`, workspace `.agents/skills`, `$MELDRA_HOME/skills`, then `$HOME/.agents/skills`. The first valid package admitted to the catalog wins a duplicate name, shadowed sources warn, and the catalog sorts by name. Missing directories are skipped and an invalid package does not block a valid one. Discovery does not recurse, search parent repositories, or read private `.claude` and `.codex` sources. Bounds: 256 direct entries, a 128 KiB file, a 16 KiB header, and 64 KiB of initial catalog JSON.

The catalog is a process-lifetime snapshot refreshed on restart or resume, while `read_skill` reads the current resource so body edits take effect immediately. Names, descriptions, and paths enter every request; bodies do not. A dedicated audited reader replaces generic file tools for skill reads. Reading never executes scripts, grants permissions, or adds tools, and skill guidance is subordinate to the user's request and runtime policy.

Skill reads reuse the workspace protections that guard configuration, task storage, and execution locks, including packages outside the workspace. Native `$MELDRA_HOME/skills` is the sole configuration-directory exception; protected descendants inside those packages stay blocked. Absolute paths, traversal, `.git`, symlinks, hard-linked files, non-regular files, binary data, and oversized resources are rejected. Package components never follow symlinks, and Darwin/Linux use `O_NOFOLLOW` and `O_NONBLOCK` to prevent final-file symlink and FIFO swaps; other platforms reject skill reads before opening files.

OpenCode's loader was examined at commit `907b3bc518fa48e90e8ec24dd327d13eee71c36c`. Its concurrent `Effect.forEach` loading overwrites duplicate map entries after warning, which does not establish deterministic last-scanner-wins behavior. Claude Code documents enterprise precedence over personal and project sources; Meldra's order is its own policy, not a universal interoperability rule. A deterministic frontend selector, explicit-only invocation, pagination, hot reload, ancestor discovery, marketplaces, installers, and remote downloads are deferred until a concrete need justifies them.

# Foreground ownership and tool outcomes

One Agent owns the conversation, one Run owns active execution, and each invocation receives its own deadline. Concurrent control callbacks journal the human request and interrupt bounded work. The serial owner applies the change after its snapshot is durable. A successful submission acknowledges receipt. A selected request remains local until the journal and snapshot establish application. An unresolved persistence or cleanup failure still terminates the turn when joined to cancellation.

Steering carries a stable control identity through compaction. Recovery checks both the conversation snapshot and verified compaction evidence before suppressing a received control. Failed policy transitions invalidate old permits and retain the stricter policy. The line interface prints a mode change because it lacks the event-driven mode indicator.

Tools expose immutable definitions and structured outcomes independent of the provider SDK and terminal. A synchronous observation belongs to one invocation, so composite handlers can record results at execution time. Artifacts carry bounded output, model excerpts carry presentation text, and manifests identify binary parts separately. An unknown effect requires explicit reconciliation. The text adapter serves callers that only consume output. Scripted-provider evaluations exercise real approvals, tools, writes and persistence against independently checked outcomes.

The serial conversation owner also presents command warnings. Dispatch validates the registered tool identity once and invokes an exact name. The caller remains responsible for serializing handlers and deciding how to reconcile side effects.

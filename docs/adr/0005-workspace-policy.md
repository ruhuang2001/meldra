# Workspace policy and approval scope

Human mode changes serialize with admission of new effects. Already admitted work can finish under its original permit. Both direct registry calls and Agent dispatch need permits. Bind approvals to the actual operation and its inspected instruction snapshot. Tool dispatch serializes mutable workspace state. Local commands expand from an immutable startup snapshot into ordinary user text.

Project rules retain their directory scope and provenance. Count encoded instruction bytes, including delimiters. Local context inspection stays independent of provider connections. Read files through protected-path checks, with binary image reads limited to explicit references. Skills discovery uses a bounded startup snapshot and rejects overfull roots to avoid filesystem-order selection. Restrict the private state exception to its configured skills directory. Open components beneath an already-open parent, reject final symlinks and avoid blocking on special files. Platforms without the required operations fail closed.

Workspace changes retain bounded before/after data for approval and undo. Represent patch renames through both paths, preserving the original content when no hunks are present. Scope rollback to directories created by that transaction and remove them deepest first using empty-directory removal so concurrent files survive. Unknown command or remote effects need separate reconciliation. Keep approval content private. Skip undo entries that exceed the whole history budget so smaller, still-usable entries survive. Read text through a bounded UTF-8 probe that accommodates a split final rune and reuse scratch storage while scanning files serially.

Workspace commands start with a narrow environment and temporary home. Validate pytest paths, node IDs, argument-file syntax, variable expansion and supported overrides before launch. Git worktree reads can execute configured filters. Git writes therefore use explicit approval, a complete staged-diff check, operation-state checks and ordinary side-effect admission per mutating subprocess. Refuse existing staged selections to protect unrelated changes. A completed preview or earlier verification command proves only its own outcome. Keep compact summaries in context and full evidence available for inspection.

Git approval previews include complete new-file content because ordinary diffs omit it. The idle context command inspects local rules without acknowledging them for a previously generated operation. Embedders own their interactive approval presentation. Showing an automatically approved operation preserves its existing decision.

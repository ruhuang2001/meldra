# Durable execution and recovery

Separate the task records, SQLite store and application execution adapter. Only the foreground owner executes work. Inspection and migrations can open records independently. Schema version advances independently of the event envelope. Acquire task and workspace leases by filesystem identity so aliases contend and genuinely distinct case-sensitive directories remain independent. Keep persistent lock inodes, protect their final path components, honor older lock locations and refuse execution on platforms without verified locking.

Acquire the SQLite write reservation before reading mutable state so competing writers cannot invalidate a deferred-transaction snapshot. Check the schema before bounded index and migration writes. Permit independent rollback of optional index builds at capacity and allow SQLite to recover an oversized WAL. Resolve system-owned ancestor aliases while protecting the private root and descendants. Store bounded artifacts by digest in private storage. Reclaim leftovers only under exclusive writer ownership and after checking committed references. Filter secrets and raw reasoning before persistence.

Persist intent before each effect and outcomes after execution. Use provider call IDs for replay identity. Fingerprints prove only what their recorded scope covers. Metadata alone cannot establish success after a crash. Bounded recovery queries, latest process rows and verified excerpts keep inspection independent of total history. Acquire new leases for explicit reconciliation, retain terminal Run history, and mark missing evidence unknown. Historical PIDs and handles are evidence only. A process belongs to its Run even after its start call succeeds. Check ownership and effects independently of reaping. Test crashes after observable effects, including children that retain descriptors, and limit cleanup to fixture-owned processes.

Import legacy sessions by source ID and content digest before changing their revision. Retain the original JSON and allow even a corrupt task snapshot to shadow it. After atomic rename, sync the parent directory on filesystems that support it. Create missing directories one at a time and record each creation so a partial failure can be rolled back. Distinguish failure before replacement from a committed replacement whose durability is uncertain. A generic saver can fail after writing, so restore conservatively. A fatal session write remains fatal even if the ledger succeeds. Persist cancellation and known outcomes using fresh bounded contexts when an operation deadline expires.

Use request watermarks and durable events to recover gaps around snapshot commits without conflating repeated requests. Keep idle metadata operations under leases and avoid creating a task-era snapshot before legacy import. Fork only from resolved evidence, preserve referenced attachments and summaries, retain stable session pointers, reset model-specific calibration and hold the old lease until the switch completes. Restore undo evidence under the same limits as interactive changes. A suspended approval resumes only a clean call with matching persisted preview and canonical arguments.

The process manager's mutex protects shared handle state. Current ownership can record lifecycle evidence while launch specifications and completed states remain immutable. Session listing returns aggregate diagnostics and omits filenames and errors that may expose prompts, summaries or response IDs. A concrete store owns selection and listing, while runners use the narrower persistence interface. Fault-injection tests simulate a directory-sync failure after rename, reload through recovery, and require an uncertain replacement to block inference. Ownership files remain protected even inside a user-selected workspace. Bounded lookup requires a nonempty provider ID and loads at most one matching record.

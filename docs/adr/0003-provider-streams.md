# Responses streaming and continuation

The provider package owns SDK types, transport state, request options and synchronous observers for one serial conversation. An observer must finish promptly and avoid re-entering the client. Presentation filters apply only to displayed output. The provider result retains the original data. A per-request watchdog measures gaps between successfully decoded events. Cancellation interrupts the request and closes a blocked stream, including transports that ignore the context. A zero timeout selects the default and a negative override disables the watchdog.

Responses-compatible gateways can omit or mislabel Content-Type, deliver complete JSON to a streaming request, omit deltas or terminal output, or accept a continuation ID without retaining context. Inspect and replay a bounded prefix before giving the body to the SDK so a live SSE stream can expose its first token immediately. Bound the raw body before decoding. Compact insignificant whitespace incrementally for non-SSE conversion so the validator avoids a second full encoding or SDK-field loss. A compatible provider may retry a rejected streaming request before any text reaches the user. Tool execution starts after inference returns. Remember the provider’s streaming capability for subsequent requests.

Merge terminal output with completed stream items by stable item identity and output slot. A completed content part describes only that part. If a gateway changes both identifiers of a tool at the same slot, reconcile it as one call. Conflicting identities or complete arguments stop the turn before dispatch. A valid terminal argument list takes precedence over a streamed prefix. Compare integers exactly, including nested values. With missing message IDs, suppress only exact text duplicates. Retain partial output on failure. Present deltas once and fill any genuine trailing gap. When a gateway streams the answer but omits the output array, retain the answer. Custom endpoints receive the bounded current turn on tool continuations because some gateways accept a previous response ID without retaining its context. The default endpoint can continue by response ID. Rebuild input after steering.

Opaque items retain provider continuation fields. When shrinking a tool result, copy its item and override the actual encoded output while retaining identity and status. Test the incremental size calculation against a full encoding, including repeat compaction. Input images stay attached to the originating user message, with locally validated content and detail.

Measure each encoded conversation item once and account for array delimiters. Re-encoding the entire array after every tool-output replacement produces quadratic work on long histories. Keep credentials in the transport configuration and out of model items, results and observer events. Streaming fixtures pass through the public provider boundary so replay sees the opaque items a real provider supplies.

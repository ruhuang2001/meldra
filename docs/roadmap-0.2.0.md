# Meldra 0.2.0 发布方案

状态：实施计划，尚未实现或发布。更新日期：2026-10-01。

## 版本目标与产品约定

**0.2.0：可恢复、可追踪的前台任务执行。**

用户可以知道任务执行到了哪里、哪些工具实际完成，并在退出或异常后显式恢复。
关闭终端意味着结束当前执行；下一次启动不会自动继续工作。
不引入后台常驻服务、detach/attach、自动重启任务或远程调度。

发布的关键体验：

1. 启动任务时获得可查询的任务 ID。
2. 能查看执行记录、工具结果、审批结果和验证产物。
3. Ctrl-C、SIGTERM、终端关闭时取消当前运行，并尽力保存已知状态和清理所属命令。
4. 用户明确执行 resume 后，先核对未完成操作，再决定继续或要求处理。
5. 无法确认结果的有副作用操作不会被自动重跑。

强制终止、断电和逃离进程组的子进程不能靠信号处理保证清理。实现需要覆盖进程
所有权和恢复时核对；文档不得承诺任意情况下都能保存状态或实现外部命令恰好一次执行。

## 已有基础

基于 main `ec1cc01` 的独立分支 `codex/runtime-boundaries`：

- `451dab3`：应用、Provider、工具接口拆分；RunTurn；SessionSaver。
- `85d7aea`：运行时 benchmark、离线评估和报告工具。
- `76477ea`：benchmark 分段输出解析修复。
- 当前有 41 个微基准、32 个离线场景；本地基线 96/96 通过。
- 当前基线 make check 通过，覆盖率 80.5%；这些结果不等于未来版本已通过。
- 现有会话仍是 JSON；工具结果仍是 string/error；任务记录、恢复状态机尚不存在。

## 范围

| 必须交付 | 延后到后续版本 |
| --- | --- |
| Task / Run / ToolCall 状态模型 | 多代理自动拆解、并行写入与父任务集成 |
| 版本化任务存储和执行记录 | 自动创建 worktree 的完整管理器 |
| 结构化工具结果与审批记录 | MCP、插件市场、多模型大规模扩展 |
| 前台运行独占权、退出与显式恢复 | 常驻服务、后台继续、远程 worker |
| CLI/TUI 展示、兼容旧会话 | 通用工作流引擎和分布式消息系统 |
| 故障注入测试、可比较评估 | 任意宿主命令的恰好一次执行保证 |

本版保留未来子任务的扩展空间，但不添加没有消费者的调度抽象。多代理、独立
worktree 和共享预算仍是长期路线，不能成为 0.2.0 不断扩张的发布依赖。

## 目标架构

```text
main.go
  -> internal/app          CLI/TUI、配置和依赖组装
       -> internal/task    前台运行、状态转换、恢复策略和所有权
            -> provider    模型调用、协议续传和流式兼容
            -> tool        工具契约与执行分发
            -> store       版本化存储、事务和查询
       -> Workspace        文件/命令能力、路径策略和审批展示
```

task 不得导入 TUI、终端或模型 SDK。app 不再直接驱动所有副作用与存储细节。
按真实依赖拆包，不在本版强制搬迁所有 Workspace/UI 代码。

建议 SQLite WAL 保存任务状态、事件、调用和审批；文件系统保存有界的大日志及产物。
M1 确认驱动选择、schema、事务边界和迁移策略。驱动必须满足现有 Darwin/Linux、
amd64/arm64、CGO_ENABLED=0 发布构建要求；选择前运行小型构建验证，不改变平台承诺。
SQLite 事务只覆盖数据库记录，不能原子提交外部命令或多文件变更。

## M1：数据契约与所有权

交付：

- Task：用户目标、工作区标识、当前状态、会话关联。
- Run：一次执行尝试、开始/结束时间、结束原因、配置快照和执行者标识。
- ToolCall：调用 ID、参数摘要、执行阶段、结果、可重试属性和产物引用。
- Approval：具体操作、参数/补丁摘要、决定、工作区状态和生效范围。
- Event：任务内单调序号、事件种类、时间、Run/ToolCall 关联。
- schema_version、事务化迁移、私有目录/文件权限及大小限制。
- 同任务和同一可写工作区的跨进程独占策略，拒绝第二个写入者；不能仅依赖 PID
  或进程内 mutex。退出释放锁，重启后核对遗留状态，不自动启动任务。

状态约定：Task 表达目标整体进展，Run 保存每次尝试的不可覆盖终态。resume 新建
Run，不把旧失败/取消记录改成成功。工具状态至少包括 planned、running、succeeded、
failed、declined、cancelled、unknown；具体状态转换表和原因码在本阶段冻结。
Task 的“completed”不代表修改一定正确，验证证据和通过/失败应独立记录。

验收：合法/非法状态转换、双进程竞争、事务中断、重复迁移和旧 schema 读取均有测试；
查看任务记录不会启动模型或工具；生产 task 包不依赖 SDK/UI。

## M2：接入真实执行链路

交付：

- 工具返回结构化状态、文本、退出码、耗时、截断标记和产物引用。
- 保持模型收到的工具文本兼容，执行器通过结构化字段识别状态。
- 副作用开始前持久化调用意图，执行结束后保存结果；落盘失败必须阻止后续副作用。
- 记录审批结果；审批与操作内容绑定，不把一次批准当作全局权限。
- 模型请求、工具执行、验证和最终答复通过同一事件链关联。
- 保存运行配置中的模型、provider 标识、workspace；不记录 API key。
- 明确日志保留、输出上限、敏感数据处理；不把原始 provider reasoning 存为通用检查点。

验收：真实文件读写、补丁、命令、拒绝审批、超时和存储失败均经过新运行时；
旧 CLI/TUI 和会话测试仍通过；CLI/TUI 对同一结果展示一致。

## M3：退出与显式恢复

交付：

- 明确 signal、EOF、TUI 退出和用户取消的语义；按入口区分正常输入结束与终端挂断。
- 处理 Ctrl-C、SIGTERM、SIGHUP；取消在途模型请求和工具，停止并回收所属命令。
- 设置有界退出等待；保存可确认状态，不能把所有 interrupted 调用伪装成 cancelled。
- 启动时只检查记录；仅用户显式 resume 才创建下一次 Run。
- 文件操作通过调用记录及 before/after 摘要核对；文件已被用户修改时停止覆盖。
- 外部命令结果未知时展示记录并请求明确处理，不承诺可自动判断是否已经完成。
- 在运行前重新检查工作区和权限；内容改变或上次未执行的审批不得直接沿用。
- 恢复上下文保留用户目标、已完成步骤、关键工具结果和验证结果，不能只靠最近聊天。

验收：在意图保存前、保存后执行前、执行后结果保存前、结果保存后四个位置注入退出；
恢复不重复执行已确认操作，不静默覆盖用户改动；终端关闭测试验证前台进程及普通
子进程组退出。SIGKILL/断电测试验证后续能识别未知状态，单独报告孤儿进程清理边界。

## M4：用户入口与旧会话兼容

建议入口（M1 固化命名，保留已有命令）：

```sh
meldra                         # 默认前台运行，展示任务 ID
meldra tasks                   # 列出任务
meldra task show TASK_ID        # 查看状态、历史 Run 和待处理问题
meldra task events TASK_ID --json
meldra task resume TASK_ID      # 显式恢复，仍在前台
meldra sessions                # 保留旧会话入口
meldra resume SESSION_ID        # 兼容旧用法
```

事件 JSON 需要 schema 版本、稳定 ID、状态和结束原因；输出日志不混入 JSON stdout。
`resume latest` 的选择规则须明确且沿用工作区约束，避免恢复其他项目。

旧 JSON 会话采取可重复导入：保留原文件、记录来源 ID 和内容摘要、避免重复建任务。
历史上未保存的工具记录标记为缺失，不推断其成功或重新执行。迁移中断可以重试。
降级到 0.1.x 仅能读取原会话快照，不具备新任务记录；发布说明必须解释这一边界。

验收：旧版本会话样本、重复导入、损坏会话、迁移中断、工作区移动/丢失、未知数据库
版本均有覆盖；命令帮助和 README 与行为一致。

## M5：性能与质量门槛

- 保留 make check、race、75% 总覆盖率门槛及 benchmark 报告测试。
- 新增状态存取、事件追加、恢复扫描、长任务日志与磁盘增长的微基准。
- 离线评估增加 M1—M4 的故障/退出/并发/迁移场景；缺失、跳过、失败均不能算通过。
- 单独优化上下文压缩。当前 256 个大输出基线约 740 ms/op、776 MB/op 累计分配；
  该数字不是峰值内存。优化须保留顺序、预算和协议字段，并在同机同参数下比较。
- 新测量语义使用新 suite 版本；未变化项目保留可比较基线。共享 CI 不设噪声时间阈值。
- 发布候选安排固定小规模真实任务集：先确认模型、任务集和费用预算，再调用 API。
  记录通过率、回归任务、耗时、可得 token 和费用；缺失指标保持 unknown。
- SanityHarness 与 SWE-bench 的接入不等于质量评估已经通过。完整 SWE-bench 不作
  首个 0.2.0 的硬门槛，小规模外部验证结果须作为发布证据。

验收：所有离线正确性场景通过；原有关键场景无未解释退化；真实任务中的新增失败
经过归因和处置；覆盖率、延迟、分配和任务成功率分别报告，不合成单一分数。

## M6：预发布与正式发布

顺序：M1 → M2 → M3 → M4 → M5 → alpha → rc（按需）→ 0.2.0。
上下文压缩优化可作为独立 PR，不阻塞状态模型设计；不能因先完成重构就发布 0.2.0。

1. 第一条端到端恢复路径及基本迁移可用后，准备 `0.2.0-alpha.1`。
2. Alpha 阶段验证退出、恢复、审批、升级；记录已知限制，迭代 alpha.N。
3. 候选版本冻结 schema/CLI，执行全量门槛、跨平台启动/版本 smoke 和实际终端退出测试。
4. 发布前核对 Release Please、manifest、Git tag、二进制版本和 release notes 一致。
5. 正式发布说明包含升级/恢复示例、备份与降级办法、测试证据和残留限制。

当前 Release Please 为 main push 驱动、`prerelease: false`、manifest 为 `0.1.0`。
**预发布尚未配置**：发布准备 PR 需明确 alpha/正式版渠道及触发方式，验证版本推进，
避免提前合并 release PR 或手改 manifest 假装版本已经发布。本计划不修改发布配置。
源码 PR 按 Conventional Commits 编写，使用 squash/rebase 保持线性历史。

## 发布阻断条件

- 退出后仍意外调度新工作，或启动时自动恢复。
- 有副作用工具被错误重放，未知结果被标为成功，用户修改被覆盖。
- 并发执行绕过任务/工作区所有权，或陈旧审批可执行已变化操作。
- 旧会话迁移丢失数据、不支持重复导入或不能解释降级后可见内容。
- race、基础验证、关键离线场景或跨平台构建失败。

满足这些验收才进入 0.2.0；多代理和常驻服务不作为完成本版的条件。

## Source layout

The Mintlify content root is `docs/`; its navigation and theme are configured in
`docs/docs.json`. Existing Markdown guides are used directly by the site and
remain readable on GitHub. Do not maintain separate MDX copies of these guides.
Add new pages to the appropriate navigation group in `docs.json`.

Use relative Markdown links for pages within `docs/`. For source files or the
root README outside this content root, use full GitHub URLs. Keep images under
`docs/assets/`. Historical design notes under `superpowers/` are not in the site
navigation.

Keep a matching `.md` or `.mdx` redirect in `docs.json` for each new page. These aliases
let relative links work both on GitHub and on the site's extensionless routes.

## Release notes

The site [Changelog](changelog.mdx) is a curated, user-facing summary. Use one
Mintlify `Update` entry per published release, newest first, with its version,
release date, a few concrete improvements, any upgrade action, and links to the
release and full comparison. MDX is used here for the timeline component, not as
a second copy of an existing guide.

Keep the two histories distinct:

- Root `CHANGELOG.md` is generated by Release Please from Conventional Commits.
  Do not copy or manually rewrite that commit list into the site.
- `docs/changelog.mdx` explains what changed for users. Consolidate internal
  fixes into observable improvements; dependency churn need not be a highlight.

Draft highlights during development, but publish the entry only after the release
exists and all four platform archives and `meldra_checksums.txt` are available.
Confirm the final version and date instead of copying a pending release PR's
proposed values. New features documented on `main` before release should be
marked as unreleased; do not advertise them as available in the latest binary.

Release Please maintains a release PR as commits reach `main`; merging that PR
is the release decision. The workflow creates the GitHub release, validates its
tagged source, and then uses GoReleaser to upload artifacts. A release page alone
therefore does not prove a successful build or complete downloads. If publishing
fails, inspect the workflow and use its existing tag-repair dispatch only after
reviewing the failure. Do not move the tag to include later fixes.

## Local preview

Documentation tooling is separate from the Go build and test workflow. Install
Node.js 22 LTS or a newer supported LTS version, then run from the repository:

```sh
cd docs
npx mint@4.2.1085 dev --no-open
```

Open `http://localhost:3000`. Changes reload as you edit. The CLI can download
preview dependencies on its first run; no Meldra API key is needed. Basic page
preview does not require connecting a Mintlify account.

## Validate changes

From `docs/`, run:

```sh
npx mint@4.2.1085 validate
npx mint@4.2.1085 broken-links
```

Check representative pages in the browser as well as command output. Keep
technical claims aligned with the implementation. The existing `make check`
remains the Go/runtime gate and does not install Node or run Mintlify.

## Connect hosting

Publishing requires the repository owner's authorization in Mintlify and GitHub:

1. Create a Mintlify project and choose the existing GitHub repository
   `ruhuang2001/meldra`, rather than creating a separate starter repository.
2. Install the Mintlify GitHub App with access to this repository only.
3. Select the publishing branch, normally `main`, and set the documentation
   subdirectory to `docs` (the directory containing `docs.json`).
4. Review the first build in the Mintlify dashboard and use the site address
   assigned to the project. Configure a custom domain separately if desired.

Once connected, pushes to the configured branch deploy documentation changes.
This repository does not assume a site URL or configure a domain for you. Account
features and pricing depend on the Mintlify plan you select.

See Mintlify's [GitHub connection guide](https://www.mintlify.com/docs/deploy/github)
and [CLI reference](https://www.mintlify.com/docs/cli) for current platform details.
